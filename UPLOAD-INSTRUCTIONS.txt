GitHub Pages 修复版（基于 V28，含 8 张原照片）

只需上传本包内的文件，不用打开旧网站再下载，不用重新挂照片。
1. 解压 Birthday-GitHub-Pages-Fix.zip。
2. 打开 https://github.com/barry1561088457-source/birthday ，保持 main 分支。
3. Add file → Upload files；打开解压后的文件夹，把里面全部文件一起拖入上传框。
4. index.html、app-*.js、style-*.css、font-*、texture-* 必须直接位于仓库根目录。
   不要上传 ZIP，不要把外层文件夹整体作为子文件夹上传，不要只上传 index.html。
5. 在页面底部 Commit changes，提交到 main；同名 index.html 会被更新。
6. 等待 Actions 中最新 pages build and deployment 成功，再打开：
   https://barry1561088457-source.github.io/birthday/?v=github-fix
   标题应显示「V28 GitHub Pages 修复版」。以后分享普通网址即可。

本包是所有资源都放在根目录的专用版本，不需要 assets 文件夹。
之前已上传的旧 app/style 文件可以保留，修复页面引用新的文件名。
旧 _headers、_redirects 是 Netlify 配置，GitHub Pages 不使用它们；不必为本次修复删除。
.nojekyll 是空文件；若电脑隐藏它，可在仓库 Add file → Create new file 新建同名空文件。
这些静态文件没有 Jekyll 变量，未上传 .nojekyll 也不影响本包普通文件路径。
若当前 Pages 已能显示首页，保持现有发布设置即可。
只有未配置发布源时，Settings → Pages → Deploy from a branch，main，/(root)，Save。

修复内容
HTML、脚本内原贴图和 CSS 字体路径全部改为相对路径，适配 /birthday/ 子目录。
更改后的 JS/CSS 使用新的内容哈希文件名，避免缓存与旧文件混用。
保留完整的 8 张内嵌照片、V28 模型、字体、色彩、灯光、材质、交互和只读权限。
照片、原贴图和字体字节未改。未向 GitHub 或其他托管服务提交或发布内容。
